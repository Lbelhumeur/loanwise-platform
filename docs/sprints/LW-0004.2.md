# LW-0004.2 � AWS Security Foundation

## Status

**Complete**

## Objective

Establish the AWS security foundation for LoanWise while maintaining the
DEV/PROD account boundary established by LW-0004.1.

The work will implement the appropriate DEV security baseline and document
the production security requirements that will be implemented in the future
dedicated PROD account.

### 6.1 Approved DEV Encryption Approach

- AWS-managed/default encryption is preferred where it satisfies the
  requirement.
- Existing S3 state and CloudTrail buckets use AES-256 server-side
  encryption and do not require a customer-managed KMS key at this stage.
- Secrets Manager will use the AWS-managed `aws/secretsmanager` key when
  application secrets are introduced.
- Customer-managed KMS keys remain deferred until a documented requirement
  for key-policy control, cross-account use, customer-controlled lifecycle,
  or similar capabilities exists.

### 7.1 Logging and Monitoring Implementation Decision

- CloudTrail multi-Region management-event logging is implemented in DEV.
- CloudTrail delivery and digest delivery have been independently verified.
- CloudWatch remains event/resource-driven in DEV.
- Empty CloudWatch log groups and alarms are not created merely to satisfy
  the security checklist.
- Application and service-specific log groups and alarms will be created
  with the corresponding application resources.
- Production logging and retention requirements remain defined separately
  from DEV implementation.

- [x] Define production WAF requirements.

### 8.1 AWS Security Service Implementation Decision

- GuardDuty is implemented in DEV as a Terraform-managed account-level
  security control.
- GuardDuty is enabled with a six-hour finding publication frequency.
- AWS-managed GuardDuty protection features currently enabled by the
  service are accepted as the DEV baseline.
- Advanced AI and runtime-monitoring features that remain disabled are not
  enabled in the empty DEV environment.
- GuardDuty feature-level configuration will be revisited when application
  workloads are introduced or AWS protection requirements change.
- Inspector is deferred until meaningful workloads exist to scan.
- Security Hub is deferred until there is sufficient security posture and
  finding data to justify enabling the service.
- AWS Config is deferred until meaningful resources and configuration rules
  exist.
- AWS WAF remains a production requirement and is deferred until the PROD
  web entry point exists.
- Deferred services remain documented requirements and are not considered
  implemented merely because their requirements are defined.

## Acceptance Criteria

LW-0004.2 can be closed when:

- ADR-0019 exists and is consistent with LW-0004.1.
- The LW-0004.2 architecture document exists.
- DEV security requirements are clearly separated from PROD requirements.
- The Terraform security module boundary is established.
- DEV state security is validated.
- Identity and account boundaries are documented and validated.
- Secrets and encryption boundaries are documented.
- Logging and security-service requirements are documented.
- Required resource tags are defined.
- No production application infrastructure is deployed as part of LW-0004.2.
- Validation evidence is recorded.

## Out of Scope

The following are intentionally deferred:

- Production account creation.
- Production customer data.
- Full application infrastructure.
- Production WAF deployment.
- Production backup implementation.
- Full CI/CD implementation.
- Final production RPO/RTO values.

## 4.2 Closeout

LW-0004.2 is complete for the approved DEV/POC security foundation.

The next LW-0004 work item will be selected and defined separately. No
production resources or customer data were introduced during LW-0004.2.
