# LW-0004.3 - DEV Application and Delivery Foundation

## Purpose

Establish the first application infrastructure and delivery foundation in
DEV while preserving the account, security, and Terraform boundaries
established by LW-0004.1 and LW-0004.2.

## Environment Boundary

### DEV / POC

DEV:

- Uses the existing AWS account.
- Contains synthetic data only.
- Is fully Terraform-managed.
- Is deployable through CI/CD.
- Is destroyable and rebuildable.
- Supports application development, testing, and POC work.

### PROD

PROD:

- Uses a future dedicated AWS account.
- Contains real customer data.
- Uses a protected deployment path.
- Is not deployed by the DEV workflow.

## CI/CD Boundary

The CI/CD system is shared conceptually across environments but deployed
through separate environment controls.

### DEV Pipeline

The DEV path may:

- Build.
- Test.
- Plan.
- Deploy.
- Run validation.
- Destroy.
- Rebuild.

### PROD Pipeline

The PROD path will additionally require:

- Dedicated AWS account.
- Protected environment configuration.
- Production-only security controls.
- Approval gates.
- Production data-protection controls.
- Production deployment safeguards.

The DEV workflow must not assume access to the PROD account.

## Security Boundary

The security foundation established by LW-0004.2 remains mandatory.

DEV application resources must inherit:

- Required tags.
- IAM boundaries.
- Logging requirements.
- Encryption requirements.
- Account boundary protection.

Application-specific monitoring is created with the resources it monitors.

## Out of Scope

LW-0004.3 does not include:

- Production deployment.
- Production customer data.
- Production DNS cutover.
- Final production WAF deployment.
- Final production backup/DR architecture.
- Full production approval workflow.
