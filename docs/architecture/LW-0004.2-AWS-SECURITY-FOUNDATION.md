# LW-0004.2 � AWS Security Foundation

## Purpose

Define and establish the AWS security foundation for LoanWise while preserving
the account and environment boundaries established by LW-0004.1.

## Environment Model

### DEV

DEV is the development and POC environment.

DEV:

- Uses the existing AWS account.
- Uses synthetic data only.
- Is administered through IAM Identity Center.
- Uses Terraform with an explicit AWS account boundary.
- Uses remote Terraform state in S3.
- Must not contain production customer data.

### PROD

PROD will use a dedicated AWS account.

PROD:

- Will contain real customer data.
- Will receive the production security baseline.
- Will not be implemented in the DEV account.
- Will be configured after the dedicated account is available.

## Security Layers

The security foundation is organized into the following layers.

### Identity

- IAM Identity Center provides human administrative access.
- Terraform/service execution roles remain separate from human access.
- Application roles are separate from infrastructure roles.
- Least-privilege access is required for non-administrative roles.

### Account Boundary

Environment Terraform providers use `allowed_account_ids`.

This prevents Terraform from silently operating against an unintended AWS
account.

### Terraform State

Terraform state is stored remotely in Amazon S3.

The DEV state bucket has:

- Versioning enabled.
- Server-side encryption enabled.
- Public access blocked.
- Bucket ownership enforced.
- Noncurrent-version lifecycle management.
- Terraform-managed tags.

The state bucket itself is created by the bootstrap Terraform configuration.

### Secrets

Secrets must not be stored in:

- Git.
- Terraform source files.
- Terraform variable defaults.
- Application source code.
- Plain-text configuration committed to the repository.

AWS Secrets Manager is the designated boundary for application/runtime
secrets where required.

### Encryption

Encryption requirements will use AWS KMS where customer-managed keys or
service-specific key control is required.

The specific production key architecture is deferred until the PROD account
and production data requirements are established.

### Logging and Monitoring

CloudTrail and CloudWatch form the baseline for AWS activity and operational
monitoring.

Production logging requirements will include appropriate centralized audit
and retention controls.

### Security Services

The production security baseline will evaluate and implement:

- GuardDuty.
- Inspector.
- Security Hub.
- AWS Config.

DEV will use an appropriate subset based on actual POC requirements and
cost considerations rather than duplicating every production service.

### Web Application Protection

AWS WAF is a production requirement.

It is not required merely because the DEV account exists and will not be
deployed until an actual production web entry point requires it.

## Required Tags

Terraform-managed resources should use the established tagging model.

The baseline tags include:

- `Application`
- `Environment`
- `ManagedBy`
- `Tenant`

Additional cost-allocation tags may be introduced as the platform grows.

## Security Module Boundary

Reusable security Terraform resources belong under:

`infrastructure/modules/security/`

Environment-specific composition belongs under:

`infrastructure/environments/dev/`

and:

`infrastructure/environments/prod/`

The security module must not contain environment-specific account IDs,
credentials, or production-only assumptions.

## Validation

LW-0004.2 validation will confirm:

- DEV AWS authentication works through IAM Identity Center.
- Terraform cannot target an unintended account.
- Terraform state remains remotely stored.
- Terraform state security controls remain enabled.
- Required tags are consistently defined.
- No credentials or account-specific secrets are committed.
- DEV security resources are appropriate for a synthetic-data POC.
- Production-only resources remain deferred until the PROD account exists.

## Out of Scope

LW-0004.2 does not include:

- Application infrastructure.
- Production account creation.
- Production customer data.
- Full application Cognito configuration.
- Full CI/CD implementation.
- Production WAF deployment.
- Production backup implementation.
- Final production RPO/RTO values.
